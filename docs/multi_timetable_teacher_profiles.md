# 시간표 다중화 & 교사별 계획서(인쇄 프로파일) 설계

> 작성일: 2026-08-26
> 상태: 확정 (구현 진행 중)

## 1. 요구사항

### 기존 (단일 구조)
- 시간표: 학교 1개당 1개만 등록 가능
- 인쇄 프로파일: 양식 2개 하드코딩(`pdf_export_settings_template_{0|1}.json`), 교체 건과 무관하게 전역 1세트

### 신규 요구사항
1. **시간표(학기) 다중 등록**: 이름을 부여한 여러 시간표를 등록하고 목록에서 전환
2. **시간표별 데이터 완전 분리**: 교체 목록, 결보강 데이터, 인쇄 프로파일은 시간표별로 독립
3. **교사별 계획서(인쇄 프로파일) 관리**: 시간표 안에서 교사 이름별로 계획서를 여러 개 관리

```
월계중1학기 (시간표/학기)
└── 홍길동 (교사)
    ├── 계획서1
    ├── 계획서2
    └── 계획서3
└── 김철수 (교사)
    └── 계획서1
```

4. **교체불가 공유**: 같은 시간표 안에서는 **교사가 달라도** "교체 불가" 셀을 공유
   - 교체불가 셀은 `시간표` 단위로 1세트만 존재 (모든 교사가 공유)
   - 계획서와도 무관하며, 교사 전환과도 무관
5. **일괄 출력**: 교체 목록에서 여러 건을 선택해 각 건에 지정된 계획서로 한 번에 PDF 출력
6. **교체 상태 공유**: 같은 시간표 안에서 교체 결과(누적 교체 상태)는 모든 교사·계획서가 공유
   - 교체 1건이 실행되면 그 결과는 시간표 전체에 반영됨 (교사별로 분기되지 않음)
   - 다른 교사를 교체할 때도 이전 교체가 반영된 **현재 시간표 상태**를 기준으로 검증
   - 계획서는 인쇄 설정일 뿐, 교체 상태를 복제·분기하지 않음

### 확정된 방식 (사용자 답변)
| 항목 | 결정 |
|---|---|
| 시간표 구분/전환 | 이름 부여 + 목록 전환 |
| 시간표 전환 시 교체 목록 | 시간표별 완전 분리 |
| 인쇄 프로파일 | 이름 있는 계획서 + 교사별 관리 + 교체 건에 지정 |
| 출력 단위 | 여러 건 일괄 출력 |
| 교체 건 식별자 | `ExchangeHistoryItem.id` 사용 (파생 exchangeId 금지 — 내용 기반이라 충돌 위험) |
| 시간표 테마 | v1에서 전역 유지 (추후 확장) |

## 2. 데이터 구조 (Before → After)

```
data/  (기존 → 신규)
├── timetable_file_metadata.json   ──→  timetable_registry.json        [신규·자동이전]
│   {단일 활성 시간표}                    {
│                                          "activeId": "tt_20260826_143000",
│                                          "timetables": [
│                                            { "id":      "tt_20260826_143000",
│                                              "name":    "월계중1학기",
│                                              "fileName": "2학기_전체시간표.xlsx",
│                                              "filePath": "D:/...",
│                                              "hash":     "월계중_a1b2...",
│                                              "contentHash": "a1b2...",
│                                              "registeredAt": "2026-08-26T14:30:00" }
│                                          ]
│                                        }
├── timetable_data_{hash}.json          (유지 — 내용 해시 기반, 동일 내용 시간표 공유 재사용)
├── non_exchangeable_data_{hash}.json   (유지 — 시간표 단위 1세트, 모든 교사가 공유. 계획서·교사와 무관)
├── exchange_list.json             ──→  exchange_list_{timetableId}.json      [시간표별 분리·자동이전]
│                                        {시간표 내 모든 교사·계획서가 공유하는
│                                         누적 교체 상태 (교체 결과의 단일 진실원본)}
├── substitution_plan_data.json    ──→  substitution_plan_data_{timetableId}.json [자동이전]
├── pdf_export_settings_template_{0|1}.json ──→ print_profiles_{timetableId}.json [자동이전]
│                                        {
│                                          "profiles": [
│                                            { "id": "pp_20260826_150000",
│                                              "name": "계획서1",
│                                              "teacherName": "홍길동",
│                                              "templateIndex": 0,
│                                              "fontSize": 10.0,
│                                              "remarksFontSize": 7.0,
│                                              "selectedFont": "hanbatang.ttf",
│                                              "includeRemarks": false,
│                                              "additionalFields": {},
│                                              "selectedTemplateFilePath": null }
│                                          ],
│                                          "lastUsedProfileId": "pp_..."
│                                        }
└── timetable_theme.json                (유지 — 전역)

ExchangeHistoryItem: + profileId (String?, nullable) 필드 추가
```

- ID 규칙: 시간표 `tt_{yyyyMMdd_HHmmss}`, 계획서 `pp_{yyyyMMdd_HHmmss}`
- 계획서는 평면 리스트에 `teacherName` 필드로 교사 귀속 → UI에서 교사별 그룹핑
- 계획서 이름은 교사 내에서 중복 가능하나 UI에서 경고 (권장: 고유 이름)

### ③ 계획서 출력 — 결보강 출력 탭 (교사별 계획서 바)

┌────────────────────────────────────────────────────────────────┐
│ 교사: [ 홍길동 ▼ ]                                              │
│         │ 클릭 시 펼침:                                        │
│         │  ┌──────────────┐                                   │
│         │  │ ✓ 홍길동      │ ← 현재 선택 (체크 표시)             │
│         │  │   김철수      │                                   │
│         │  │   이영희      │ ← 현재 시간표의 모든 교사           │
│         │  └──────────────┘   (엑셀 파싱 결과, 가나다순)      │
│ 계획서: [ 계획서1 ▼ ]    [＋ 새로 만들기] [✎ 이름변경] [🗑 삭제]  │
│         │ 선택 교사의 계획서만 표시                              │
├────────────────────────────────────────────────────────────────┤
│ (계획서가 없는 교사를 선택한 경우)                               │
│ ⓘ '김철수'의 계획서가 없습니다.  [＋ 새로 만들기]                │
├────────────────────────────────────────────────────────────────┤
│ 양식 [양식 1 ▼]  폰트 [한바탕 ▼]  크기 [10.0]  비고 [해제]        │
│ 교사명 [홍길동] 학교명 [월계중] 비고 내용 [      ]                │
│ 결강기간 · 입력란 (기존과 동일)                                  │
├────────────────────────────────────────────────────────────────┤
│ [PDF 미리보기]   [이 계획서에 저장]                              │
└────────────────────────────────────────────────────────────────┘

  - 교사 목록 출처: 현재 활성 시간표의 교사 목록 (TimetableData.teachers,
    엑셀 파싱 결과, 가나다순 정렬) — 별도 등록/삭제 없음
  - 계획서 드롭다운: 선택한 교사의 계획서 목록만 표시
  - 교사 전환 → 계획서 목록만 갱신 (교체불가·교체 상태는 시간표 단위 공유라 변화 없음)

  - [새로 만들기] → 현재 화면 값을 복사한 새 계획서 생성 + 이름 입력
  - [삭제] → 해당 계획서가 지정된 교체 건은 '미지정'(기본 계획서 사용)으로 자동 해제

### ⑤ 교체불가 셀 (시간표 단위 공유 규칙)

```
교체 화면의 교체불가 셀 지정 (셀 우클릭 등)
  → 저장 위치: non_exchangeable_data_{시간표hash}.json
  → 단위: 시간표 1세트 (교사 키 없음 — 모든 교사가 공유!)

  월계중1학기
  └── 교체불가 셀 1세트 ──┬── 홍길동에게도 적용
                          ├── 김철수에게도 적용
                          ├── 모든 교사에게 적용 (교사 무관)
                          └── 계획서1/2/3 공통 (계획서 무관)

  ⇒ 어떤 교사 화면에서 교체불가를 지정해도 시간표 전체에 반영
  ⇒ 계획서를 새로 만들어도 교체불가 설정이 복사/초기화되지 않음
  ⇒ 시간표를 전환하면 해당 시간표의 교체불가 데이터가 로드됨 (시간표 간 독립)
```

### ⑥ 교사 전환 (관리 방식)

```
학교(시간표) 전환 = 전역 전환 (시간표 관리 화면, 앱 전체 데이터 교체)
교사 전환        = 화면 국소 전환 (계획서 출력 탭 안에서만 수행)

┌──────────────────────────────────────────────────────┐
│ 계획서 출력 탭                                        │
│ 교사: [홍길동 ▼] ← 드롭다운 선택으로 전환              │
│        │                                             │
│        ├─ 1. 계획서 목록 → '홍길동'의 계획서로 교체     │
│        │     (계획서 없으면 "새로 만들기" 안내)         │
│        ├─ 2. 교체불가 셀   → 변화 없음 (시간표 공유)    │
│        ├─ 3. 교체 목록     → 변화 없음 (시간표 공유)    │
│        └─ 4. 마지막 선택 교사 저장 → 재시작 시 복원      │
│                                                      │
│ 교사 목록 출처: 현재 활성 시간표의 교사 목록            │
│   (ExcelService가 파싱한 TimetableData.teachers)      │
│ 교사 추가/삭제: 불가 (엑셀 원본에 있는 교사만 존재)      │
└──────────────────────────────────────────────────────┘

저장 구조 (print_profiles_{timetableId}.json):
  { "profiles": [...],
    "lastSelectedTeacher": "홍길동",     ← 교사 전환 시 갱신
    "lastUsedProfileId": "pp_..." }     ← 교사별 마지막 계획서 복원용

다른 화면의 교사 선택과의 관계:
  - 교체 관리 화면: 시간표 전체 그리드 표시 (교사 전환 개념 없음)
  - 개인 시간표 화면: 자체 교사 선택 UI 유지 (기존과 동일, 독립 동작)
```

## 4. 핵심 동작 흐름

```
[시간표 추가]
[+ 시간표 추가] → 엑셀 파일 선택 → 이름 입력 다이얼로그(기본값: 파일명)
  → 파싱 → timetable_data_{hash}.json 저장(해시 중복 재사용)
  → registry.timetables에 항목 추가 → activeId로 지정 여부 확인

[시간표(학교) 전환 — 전역]
목록 [전환] → 확인 → registry.activeId 갱신
  → 시간표 본문 로드(timetable_data_{hash})
  → 교체 목록 로드(exchange_list_{id}) ← 누적 교체 상태 포함
  → 계획서/결보강 데이터 로드({id} 스코프)
  → 교체불가 로드(non_exchangeable_data_{hash}) ← 시간표 단위 공유
  → 전체 화면 상태 리셋(stateResetProvider) → UI 갱신

[교사 전환 — 계획서 출력 탭 국소]
교사 드롭다운 선택 → 해당 교사의 계획서 목록 로드
  → lastSelectedTeacher 저장 → 교체불가·교체 상태는 무변경

[계획서 생성/지정/출력]
결보강 출력 탭에서 교사 선택 → 계획서 선택/생성 → 설정 편집
  → [이 계획서에 저장] 또는 내용 입력 그리드에서 행별 지정
  → [일괄 출력] → 건별 profileId로 계획서 로드
  → 미지정 건은 lastUsedProfileId 사용
  → 폴더 선택(1회) → 건별 PDF 생성 → 결과 요약

[마이그레이션 (앱 시작 1회, 멱등)]
registry.json 없음? ──아니오→ 스킵
   │예
구 metadata 존재? → 레지스트리 생성(이름=기존 fileName, id=tt_초기)
exchange_list.json → exchange_list_{id}.json 이동
substitution_plan_data.json → {id} 스코프로 이동
pdf template_{0|1} → 계획서 2개("양식 1","양식 2")로 이전 (teacherName: 기본 교사명 또는 '')
실패 시에도 원본 파일 보존 (삭제하지 않음)
```

## 6. 리스크 및 유의사항

1. **두 교체 식별자 공존**: `ExchangeHistoryItem.id`(안정) vs 파생 `exchangeId`(내용 기반, 재교체 시 충돌 가능) — 계획서 지정 키는 반드시 `item.id` 사용
2. **기존 설치 PC 마이그레이션**: 원본 파일 삭제 금지(보존 후 이동), 마이그레이션은 멱등하게
3. **테스트 부재 영역**: `TimetableStorageService`, `PdfExportSettingsStorageService`, `ExchangeListStorageService`는 기존 테스트 없음 — 스키마 변경 전 테스트 선작성
4. **미사용 API 정리 대상**: `PdfExportSettingsStorageService.saveTeacherAndSchoolName()` 등 호출부 없는 메서드 — 다중화 작업 시 정리
5. **교체불가 공유 보장**: 계획서 복제/생성 로직에서 교체불가 데이터를 건드리지 않도록 저장 계층 분리 유지
