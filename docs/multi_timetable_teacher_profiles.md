> 작성일: 2026-08-26
> 최종 수정: 2026-08-31 (§10 1~6단계 구현 완료 — 날짜 기반 구조 전환 · 마이그레이션 없음 정책 반영)
> 상태: §1~§9 구현 완료 (반영 결과는 §8, 점검은 §9) · **§10 설계 확정 · 미구현**

## 1. 요구사항

### 기존 (단일 구조)
- 시간표: 학교 1개당 1개만 등록 가능
- 인쇄 프로파일: 양식 2개 하드코딩(`pdf_export_settings_template_{0|1}.json`), 교체 건과 무관하게 전역 1세트

### 신규 요구사항
1. **시간표(학기) 다중 등록**: 이름을 부여한 여러 시간표를 등록하고 목록에서 전환
2. **시간표별 데이터 완전 분리**: 교체 목록, 결보강 데이터, 인쇄 프로파일은 시간표별로 독립
3. **교사별 계획서(인쇄 프로파일) 관리**: 시간표 안에서 교사 이름별로 계획서를 여러 개 관리

```
월계중1학기 (시간표/학기)
└── 홍길동 (교사)
    ├── 계획서1
    ├── 계획서2
    └── 계획서3
└── 김철수 (교사)
    └── 계획서1
```

4. **교체불가 공유**: 같은 시간표 안에서는 **교사가 달라도** "교체 불가" 셀을 공유
   - 교체불가 셀은 `시간표` 단위로 1세트만 존재 (모든 교사가 공유)
   - 계획서와도 무관하며, 교사 전환과도 무관
5. **일괄 출력**: 교체 목록에서 여러 건을 선택해 각 건에 지정된 계획서로 한 번에 PDF 출력
6. **교체 상태 공유**: 같은 시간표 안에서 교체 결과(누적 교체 상태)는 모든 교사·계획서가 공유
   - 교체 1건이 실행되면 그 결과는 시간표 전체에 반영됨 (교사별로 분기되지 않음)
   - 다른 교사를 교체할 때도 이전 교체가 반영된 **현재 시간표 상태**를 기준으로 검증
   - 계획서는 인쇄 설정일 뿐, 교체 상태를 복제·분기하지 않음

### 확정된 방식 (사용자 답변)
| 항목 | 결정 |
|---|---|
| 시간표 구분/전환 | 이름 부여 + 목록 전환 |
| 시간표 전환 시 교체 목록 | 시간표별 완전 분리 |
| 인쇄 프로파일 | 이름 있는 계획서 + 교사별 관리 + 교체 건에 지정 |
| 출력 단위 | 여러 건 일괄 출력 |
| 교체 건 식별자 | `ExchangeHistoryItem.id` 사용 (파생 exchangeId 금지 — 내용 기반이라 충돌 위험) |
| 시간표 테마 | v1에서 전역 유지 (추후 확장) |

### 교사·학교명을 시간표 속성으로 옮기는 이유

기존에는 교사명·학교명이 앱 전역 설정에 **자유 입력 문자열**로 저장됐다. 계층 정의상
교사는 시간표에 종속되는데 저장 위치가 계층과 어긋나 다음 문제가 생긴다.

- 시간표를 전환해도 교사명이 그대로 남아, 다른 학교 시간표에 이전 학교 교사명이 붙는다
- 오타가 나면 교체 화면 행 하이라이트·개인 시간표·계획서 교사명이 **조용히 동시에** 빗나간다
  (엑셀 교사 목록이라는 정답지가 있는데 자유 입력을 받고 있었다)
- 시간표는 사실상 "학교 + 학기" 단위(`월계중2학기`)이므로 학교명도 시간표 속성이다

⇒ 두 값을 `TimetableRegistryEntry`로 옮기고, **교사는 드롭다운(엑셀 교사 목록)으로만**
   선택하게 해 존재하지 않는 교사를 고를 수 없게 만든다.

**소비처 3곳**을 전역 설정 대신 활성 엔트리에서 읽도록 바꾼다.

| 소비처 | 위치 | 용도 |
|---|---|---|
| 교체 화면 행 하이라이트 | `exchange_screen.dart` | 내 시간표 행 강조 |
| 개인 시간표 기본 교사 | `personal_schedule_screen.dart` | 초기 표시 교사 |
| 계획서 교사명 자동 입력 | `substitution_output_widget.dart` | PDF 교사명·학교명 |

개인 시간표 화면은 `teacherName`을 **기본값으로만** 쓰고, 거기서 다른 교사를 골라도
`teacherName`을 덮어쓰지 않는다 — 남의 시간표를 잠깐 보는 것이 그 화면의 용도다.

- ID 규칙
  - 시간표: `tt_{yyyyMMdd_HHmmss}`
  - 계획서: `pp_{yyyyMMdd_HHmmss_microsecond_seq}` — 같은 초에 연속 생성해도 충돌하지 않도록
    마이크로초와 프로세스 내 시퀀스를 포함한다. ID는 절대 재사용하지 않는다
    (삭제된 계획서를 가리키는 `profileId`가 새 계획서에 잘못 붙는 것을 원천 차단).
- 계획서는 평면 리스트에 `teacherName` 필드로 교사 귀속 → UI에서 교사별 그룹핑
- **이름 중복 정책**
  - 계획서 이름: 같은 교사 안에서 중복 가능하나 저장 전 경고 (권장: 고유 이름)
  - 시간표 이름: 중복 가능하나 등록·이름 변경 시 경고
    ("같은 이름의 시간표가 이미 있습니다. 목록에서 구분이 어려워집니다.")
    — 전환·삭제 다이얼로그가 이름만으로 대상을 지칭하므로 중복은 오조작 위험이 크다.

### ② 시작 화면 (`start_content_screen`) — 시간표 카드가 계층의 루트

기존 홈은 시간표 배너와 **무관한 전역 '기본 정보'(교사명·학교명) 카드**가 평평하게
나열돼 있어 계층이 드러나지 않았다. 아래처럼 교사·학교명·계획서를 시간표 카드
**안쪽**으로 넣어, 들여쓰기가 곧 종속 관계를 나타내게 한다.

**A. 기본 상태**

```
┌────────────────────────────────────────────────────────────────────┐
│  🗓  월계중2학기                                       [ 전환 ▼ ]  │
│      2학기 전체시간표 확정(0820).xlsx · 교사 43명 · 8/20 등록      │
│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 👤 교사      [ 정원길                             ▼ ]        │  │
│  │              이 시간표의 교사 목록에서 선택                  │  │
│  │                                                              │  │
│  │ 🏫 학교명    [ 월계중학교                            ]       │  │
│  │              계획서 인쇄에 사용됩니다                        │  │
│  │                                                              │  │
│  │ 📄 계획서     계획서1 · 계획서2                   [ 관리 > ] │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│                            [ ＋ 시간표 추가 ]   [ 시간표 관리 > ]  │
└────────────────────────────────────────────────────────────────────┘
```

- **교사는 반드시 드롭다운**(그 시간표의 엑셀 교사 목록). 자유 입력을 없애면
  오타로 하이라이트가 빗나가는 문제가 구조적으로 사라진다
- **[저장] 버튼 제거** — 교사는 선택 즉시 확정, 학교명은 포커스 이탈 시 자동 저장
  (기존처럼 저장을 눌러야 반영되는 구조는 잊기 쉽다)
- 기존 `기본 정보` 카드는 제거하고 이 카드에 흡수한다

**B. 전환 드롭다운 (진입점 통합)**

```
┌────────────────────────────────────────────────────────────────────┐
│  🗓  월계중2학기                                       [ 전환 ▼ ]  │
│      2학기 전체시간표 확정(0820).xlsx                              │
│                          ┌────────────────────────────────────┐    │
│                          │ 🔍 시간표 검색…                    │    │
│                          ├────────────────────────────────────┤    │
│                          │ ✓ 월계중2학기                      │    │
│                          │     정원길 · 계획서 2 · 교체 3건   │    │
│                          │   월계중1학기                      │    │
│                          │     정원길 · 계획서 3 · 교체 8건   │    │
│                          │   상계중1학기                      │    │
│                          │     ⚠ 교사 미지정 · 계획서 0       │    │
│                          ├────────────────────────────────────┤    │
│                          │ ＋ 시간표 추가…                    │    │
│                          │ ⚙ 시간표 관리…                     │    │
│                          └────────────────────────────────────┘    │
└────────────────────────────────────────────────────────────────────┘
```

- 각 행에 그 시간표의 **교사 · 계획서 수 · 교체 건수**를 함께 표시한다
  → 전환하면 무엇이 따라오는지 고르기 전에 알 수 있다
- 기존 `[변경 >]` 링크와 `[시간표 변경/추가]` 버튼은 **이 드롭다운으로 통합해 제거**한다
  (같은 관리 화면으로 가는 진입점이 3개나 중복돼 있었다)

**C. 시간표 미등록**

```
┌────────────────────────────────────────────────────────────────────┐
│                                                                    │
│                  📋  등록된 시간표가 없습니다                      │
│                                                                    │
│       엑셀 시간표 파일을 등록하면 교체 관리를 시작합니다           │
│                                                                    │
│                     [ ＋ 시간표 파일 등록 ]                        │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

교사·학교명·계획서 영역은 **아예 그리지 않는다.** 시간표가 없으면 교사 목록 자체가
존재하지 않으므로, 빈 입력란을 보여주는 것은 거짓 정보다.

│                                                                    │
│  ┌──────────────────────────────────────────────────────────────┐  │

│  │              ⚠ 선택하면 교체 화면에서 내 시간표 행이        │  │
│  │                 강조되고, 계획서 교사명이 자동 입력됩니다    │  │
│  │                                                              │  │
│  │ 🏫 학교명    [ 상계중학교                            ]       │  │
│  │                                                              │  │
│  │ 📄 계획서     ───── 교사 선택 후 사용 가능 ─────    (비활성) │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│                            [ ＋ 시간표 추가 ]   [ 시간표 관리 > ]  │

계획서 줄은 교사를 고르기 전까지 비활성(회색)으로 둔다 — 계획서는 교사에 귀속되므로
교사 없이 만들 수 없다.

### ③ 계획서 출력 — 결보강 출력 탭 (교사별 계획서 바)

```
┌────────────────────────────────────────────────────────────────┐
│ 👤 교사   [ 정원길 (시간표에 설정된 교사)        ▼ ]             │
│           │ 클릭 시 펼침 (교사 수가 많아 검색 입력 지원):        │
│           │  ┌───────────────────────┐                        │
│           │  │ [🔍 이름 검색…       ] │                        │
│           │  │ ✓ 정원길         · 2  │ ← 현재 선택 / 계획서 수  │
│           │  │   김철수         · 0  │ ← 0이면 계획서 없음      │
│           │  │   이영희         · 1  │                        │
│           │  └───────────────────────┘  (엑셀 파싱, 가나다순)  │
│ 📄 계획서 [ 계획서1 ●                          ▼ ]  [＋][✎][🗑] │
│           │ 선택 교사의 계획서만 표시 + 맨 위에 '미지정' 항목     │
│           │ ● = 저장하지 않은 변경 있음                          │
├────────────────────────────────────────────────────────────────┤
│ (계획서가 없는 교사를 선택한 경우)                               │
│ ⓘ '김철수'의 계획서가 없습니다.  [＋ 새로 만들기]                │
├────────────────────────────────────────────────────────────────┤
│ 양식 [양식 1 ▼]  폰트 [한바탕 ▼]  크기 [10.0]  비고 [해제]        │
│ 교사명 [정원길] 학교명 [월계중학교]  ← 시간표 설정에서 자동 채움  │
│ 결강기간 · 입력란 (기존과 동일)                                  │
├────────────────────────────────────────────────────────────────┤
│ [PDF 미리보기]   [이 계획서에 저장 ('계획서1')]                   │
└────────────────────────────────────────────────────────────────┘

  [기본 규칙]
  - 교사 목록 출처: 현재 활성 시간표의 교사 목록 (TimetableData.teachers,
    엑셀 파싱 결과, 가나다순 정렬) — 별도 등록/삭제 없음
  - **기본 선택은 시간표에 설정된 교사(`teacherName`)**. 다른 교사의 계획서를
    만들 때만 바꾼다. 여기서 다른 교사를 골라도 `teacherName`은 덮어쓰지 않는다
    (탭 안에서만 유효한 국소 전환. §3⑥과 동일 원칙)
  - 교사명·학교명 입력란은 활성 시간표의 `teacherName`·`schoolName`으로 자동
    채워진다 → 사용자가 매번 타이핑할 일이 없다
  - 교사 드롭다운은 **검색 입력을 지원**하고 항목마다 **계획서 개수를 표시**한다
    (중학교 기준 교사 50~80명. 단순 스크롤 목록이면 하나씩 눌러봐야
     계획서 유무를 알 수 있어 탐색 비용이 크다)
  - 계획서 드롭다운: 선택한 교사의 계획서 목록 + 맨 위 '미지정 (양식 설정 사용)' 항목
    → 계획서를 고른 뒤에도 언제든 미지정으로 되돌릴 수 있어야 한다(§4④와 동일 규칙)
  - 교사 전환 → 계획서 목록만 갱신 (교체불가·교체 상태는 시간표 단위 공유라 변화 없음)
  - 계획서 없는 교사 → 안내 메시지 + [새로 만들기] 진입 유도
  - [＋ 새로 만들기] → 현재 화면 값을 복사한 새 계획서 생성 + 이름 입력
    (기본 이름 `계획서{n+1}`. 교사 미선택 상태면 "교사를 먼저 선택하세요" 안내)
  - [✎ 이름변경] / [🗑 삭제]는 계획서가 선택된 경우에만 활성화
  - 관리 버튼은 아이콘 전용이며 각각 툴팁('새로 만들기'/'이름 변경'/'삭제')을 갖는다

  [미저장 변경 보호 — 필수]
  계획서 설정은 [이 계획서에 저장]을 눌러야 기록된다. 따라서:
  - 화면 값이 선택 계획서와 달라지면 계획서 이름 옆에 ● 표시(dirty)
  - dirty 상태에서 **교사 전환 / 계획서 전환 / 탭 이탈 / 시간표 전환**을 시도하면
    확인 다이얼로그를 띄운다
      ┌──────────────────────────────────────┐
      │ 저장하지 않은 변경이 있습니다        │
      │ '계획서1'의 변경 내용을 저장할까요?  │
      │      [취소]  [저장 안 함]  [저장]    │
      └──────────────────────────────────────┘
  - 확인 없이 덮어쓰면 폰트·크기·비고·학교명 편집이 조용히 사라진다
    (계획서를 여러 개 두는 기능 특성상 드롭다운 왕복이 잦아 반드시 재현됨)

  [삭제 후 선택 규칙 — 필수]
  - [🗑 삭제] → 확인 다이얼로그("이 계획서가 지정된 교체 건은 미지정 상태가 됩니다")
  - 삭제 성공 후 **같은 교사의 남은 계획서 중 첫 번째를 자동 선택**한다
  - 남은 계획서가 없으면 미지정 + "'○○'의 계획서가 없습니다" 안내를 표시한다
  - 무선택(빈 화면) 상태로 두지 않는다 — 안내도 저장 버튼도 없는 사각지대가 생긴다
  - 삭제된 계획서를 가리키던 교체 건의 `profileId`는 **조회 시 미지정으로 처리**한다
    (레코드에서 즉시 제거하지는 않음. 계획서 ID는 재사용되지 않으므로 안전)
```

### ④ 계획서 출력 — 내용 입력 탭 (일괄 출력)

```
┌────────────────────────────────────────────────────────────────┐
│ 교체 목록            [2건 일괄 출력]  [전체선택] [선택해제]       │
├───┬───────┬─────────┬────────────┬─────────────┬──────────────┤
│ ☑ │ 교사   │ 결강일   │ 결강 교시   │ 계획서       │ 출력          │
├───┼───────┼─────────┼────────────┼─────────────┼──────────────┤
│ ☑ │ 홍길동 │ 8/27(목) │ 3교시 수학  │ [계획서1  ▼]  │ ✓ 08-26 출력 │
│ ☑ │ 홍길동 │ 8/28(금) │ 5교시 국어  │ [계획서2  ▼]  │              │
│ ☐ │ 김철수 │ 8/31(월) │ 2교시 음악  │ [미지정    ▼] │              │
└───┴───────┴─────────┴────────────┴─────────────┴──────────────┘
     ↑ 행별 드롭다운에는 "그 행 교사"의 계획서만 표시
       + '미지정' 항목 + 맨 아래 '＋ 새 계획서…' 항목

  [행별 계획서 드롭다운]
  - 항목 구성: 미지정 / 그 행 교사의 계획서들 / ＋ 새 계획서…
  - **'＋ 새 계획서…'는 필수**. 계획서가 0개인 교사 행에서 이 항목이 없으면
    결보강 출력 탭 이동 → 교사 선택 → 생성 → 다시 돌아오기를 건수만큼 반복해야 한다.
    선택 시 그 자리에서 이름 입력 다이얼로그 → 생성 → 그 행에 즉시 지정
  - 선택 즉시 `ExchangeHistoryItem.profileId`에 저장(별도 저장 버튼 없음)

  [일괄 출력 버튼]
  - 라벨은 선택 건수를 반영: `2건 일괄 출력`
  - **선택 0건이면 버튼을 비활성화**한다(누른 뒤 에러 스낵바를 띄우지 않는다)
  - 삭제된 교체 건이 선택 집합에 남아 있으면 카운트에서 제외한다

  [출력 흐름]
  [일괄 출력] → 저장 폴더 1회 선택 → 진행 다이얼로그 → 완료 요약
  ┌──────────────────────────────────────┐
  │ 일괄 출력 중…            2 / 5       │
  │ ▓▓▓▓▓▓▓▓░░░░░░░░░░░                  │
  │ 홍길동_0828_5교시국어.pdf            │
  │                        [취소]        │
  └──────────────────────────────────────┘
  - 건당 수 초가 걸릴 수 있어 **진행률과 취소가 필요**하다.
    스낵바 하나만 띄우고 블로킹하면 10건 이상에서 멈춘 것처럼 보인다
  - [취소] → 진행 중인 1건까지만 마치고 중단, 요약에 "취소됨 n건" 표시
  → 완료 다이얼로그: "5건 중 4건 출력 성공, 1건 실패" (실패 시 건별 사유 표시)

  [자동 파일명 규칙]
  기본형: {교사명}_{결강일}_{교시과목}.pdf     예) 홍길동_0827_3교시수학.pdf
  - 값은 **그 교체 건의 첫 행** 기준으로 만든다
  - 한 건이 여러 행(다교시·다일자)이면 대표성이 없으므로 범위·건수를 덧붙인다
      여러 날짜: 홍길동_0827-0828_3교시수학외4건.pdf
      같은 날 여러 교시: 홍길동_0827_3교시수학외2건.pdf
  - 파일명 금지 문자(`< > : " / \ | ? *`·공백)는 `_`로 치환
  - 중복 시 `_2`, `_3` 접미사 — **실행 내 중복과 디스크 기존 파일을 모두 회피**한다
    (덮어쓰기 방지). 단, 접미사만으로는 내용 구분이 안 되므로 위 범위 표기를 우선한다
```

### ⑤ 교체불가 셀 (시간표 단위 공유 규칙)

```
교체 화면의 교체불가 셀 지정 (셀 우클릭 등)
  → 저장 위치: non_exchangeable_data_{시간표hash}.json
  → 단위: 시간표 1세트 (교사 키 없음 — 모든 교사가 공유!)

  월계중1학기
  └── 교체불가 셀 1세트 ──┬── 홍길동에게도 적용
                          ├── 김철수에게도 적용
                          ├── 모든 교사에게 적용 (교사 무관)
                          └── 계획서1/2/3 공통 (계획서 무관)

  ⇒ 어떤 교사 화면에서 교체불가를 지정해도 시간표 전체에 반영
  ⇒ 계획서를 새로 만들어도 교체불가 설정이 복사/초기화되지 않음
  ⇒ 시간표를 전환하면 해당 시간표의 교체불가 데이터가 로드됨 (시간표 간 독립)
```

### ⑥ 교사 전환 (관리 방식)

```
학교(시간표) 전환 = 전역 전환 (시간표 관리 화면, 앱 전체 데이터 교체)
교사 전환        = 화면 국소 전환 (계획서 출력 탭 안에서만 수행)

┌──────────────────────────────────────────────────────┐
│ 계획서 출력 탭                                        │
│ 교사: [홍길동 ▼] ← 드롭다운 선택으로 전환              │
│        │                                             │
│        ├─ 1. 계획서 목록 → '홍길동'의 계획서로 교체     │
│        │     (계획서 없으면 "새로 만들기" 안내)         │
│        ├─ 2. 교체불가 셀   → 변화 없음 (시간표 공유)    │
│        ├─ 3. 교체 목록     → 변화 없음 (시간표 공유)    │
│        └─ 4. 마지막 선택 교사 저장 → 재시작 시 복원      │
│                                                      │
│ 교사 목록 출처: 현재 활성 시간표의 교사 목록            │
│   (ExcelService가 파싱한 TimetableData.teachers)      │
│ 교사 추가/삭제: 불가 (엑셀 원본에 있는 교사만 존재)      │
└──────────────────────────────────────────────────────┘

저장 구조 (print_profiles_{timetableId}.json):
  { "profiles": [...],
    "lastSelectedTeacher": "홍길동",     ← 교사 전환 시 갱신
    "lastUsedProfileId": "pp_..." }     ← 교사별 마지막 계획서 복원용

다른 화면의 교사 선택과의 관계:
  - 교체 관리 화면: 시간표 전체 그리드 표시 (교사 전환 개념 없음)
  - 개인 시간표 화면: 자체 교사 선택 UI 유지 (기존과 동일, 독립 동작)
```

## 6. 리스크 및 유의사항

1. **두 교체 식별자 공존**: `ExchangeHistoryItem.id`(안정) vs 파생 `exchangeId`(내용 기반, 재교체 시 충돌 가능) — 계획서 지정 키는 반드시 `item.id` 사용
2. **마이그레이션 없음**: 구 단일 구조 데이터의 자동 이전은 제공하지 않음 — 기존 시간표는 관리 화면에서 다시 등록
3. **교체불가 공유 보장**: 계획서 복제/생성 로직에서 교체불가 데이터를 건드리지 않도록 저장 계층 분리 유지
4. **스코프 필수 정책**: 교체 목록·결보강·교체불가 저장/로드는 시간표 스코프가 없으면 건너뛰며, 레거시 전역 파일로 폴백하지 않음
5. **미저장 변경 유실**: 계획서 설정은 수동 저장이므로 드롭다운 전환이 곧 덮어쓰기가 된다 — dirty 표시 + 전환 시 확인이 없으면 편집 내용이 조용히 사라짐 (§3③)
6. **파괴적 초기화의 무확인 실행**: 동일 경로 파일 재선택 시의 교체 목록 정리는 사용자 눈에 "같은 파일을 다시 골랐을 뿐"으로 보인다 — 반드시 사전 확인 (§3①)
7. **미지정 폴백 대상**: 절대 `lastUsedProfileId`(교사 무관 전역값)를 쓰지 않는다 — 다른 교사 이름이 찍힌 PDF가 나옴 (§4)
8. **다행 교체 건의 파일명**: 첫 행만으로 이름을 만들면 다교시·다일자 건이 서로 구분되지 않는다 — 범위·건수 표기 필요 (§3④)
9. **전역 교사명 잔존 금지**: `defaultTeacherName`/`defaultSchoolName`을 읽는 코드가 한 곳이라도 남으면 진실원본이 둘이 되어 시간표별 값과 어긋난다 — 소비처 3곳을 모두 옮기고 저장·읽기 코드를 함께 제거할 것 (§2)
10. **교사 선택의 국소성**: 결보강 출력 탭·개인 시간표 화면에서 다른 교사를 골라도 `teacherName`을 덮어쓰지 않는다 — 남의 시간표 열람이 내 설정을 바꾸면 안 된다

## 7. 검증 결과 보완 사항 (점검 확정 동작)

1. **교체불가 해시**: 레지스트리 활성 시간표 해시 기준 (전환 대응)
2. **동일 파일 재선택**: 관리 화면에서 동일 경로 파일을 다시 선택하면 **새 항목을 만들지 않고 기존 항목을 갱신**한다. 내용(contentHash)이 바뀐 경우에만 해당 시간표의 교체 목록·결보강 스코프 데이터를 정리하며(계획서는 유지), **정리 전에 삭제 대상 건수를 명시한 확인 다이얼로그를 띄우고 [취소] 시 아무것도 변경하지 않는다**(§3①).
3. **홈 우회 차단**: 홈의 파일 선택 버튼은 시간표 관리 화면으로 연결 (스코프 불일치 방지). '해제' 버튼 제거 — 시간표를 비활성으로 되돌리는 수단은 제공하지 않으며, 더 쓰지 않는 시간표는 **삭제**로 정리한다.
4. **고스트 데이터 차단**: 활성 시간표가 없으면(전체 삭제) 어떤 파일도 로드하지 않고 메모리만 초기화. 활성 시간표를 삭제한 경우에는 남은 시간표 중 첫 번째로 자동 전환하고, 그 사실을 삭제 다이얼로그에 미리 고지한다.
5. **전환 시 정리**: undo/redo 스택 초기화 + 교체 화면 UI 상태 리셋 선행
6. **계획서 미지정 해제**: 내용 입력 그리드와 **결보강 출력 탭의 계획서 드롭다운 양쪽 모두** '미지정' 항목을 제공해 지정 해제가 가능해야 한다 (한쪽에만 있으면 되돌릴 방법이 없어짐)
7. **일괄 출력 안전장치**: 양식 인덱스 범위 검증, 사용자 지정 템플릿 파일 존재 확인, 출력 파일명이 실행 내 중복 + 디스크 기존 파일 모두 회피 (덮어쓰기 방지)
8. **레거시 폴백 제거**: 구 단일 메타데이터·전역 파일 참조 코드 전면 제거 (마이그레이션 불필요 정책 반영). 단 `pdf_export_settings_template_{0|1}.json`은 **계획서 미지정 건의 인쇄 설정 폴백**으로 계속 사용하므로 제거 대상이 아니다.

## 10. 날짜 기반 구조 전환 설계 (2026-08-30)

> 상태: **설계 확정 · 미구현**
> 배경: §1~§9는 "시간표 다중화"를 다뤘으나, 시간표 **내부의 시간 모델**은 손대지 않았다.
> 다중 시간표·다중 교사가 실제로 쓰이기 시작하면서 이 모델의 한계가 드러났다.

### 10.1 문제 — 한 문장

**교체는 "8/27 목요일 3교시 1회"인데, 저장은 "목요일 3교시 영구"로 된다.**

### 10.2 현재 구조 (코드 확인 결과)

| 요소 | 날짜 개념 | 근거 |
|---|---|---|
| `TimeSlot` | **없음**. `dayOfWeek 1~5` + `period`뿐 | `lib/models/time_slot.dart:13-14` |
| 교체 실행 | **"교체 뷰" 토글 시** `TimeSlot.moveTime()`으로 마스터 슬롯을 제자리에서 파괴적 변형하고, 원본은 `backupData`에 백업 → 토글 해제 시 백업으로 복원 (아래 §10.2.1 정정 참조) | `exchange_service.dart:373, 490, 815` / `exchange_view_provider.dart:91, 201` |
| `ExchangeHistoryItem` | `timestamp`는 **실행 시각**일 뿐. 결강일 필드 없음 | `exchange_history_item.dart:14` |
| 결강일·교체일 | `SubstitutionPlanState.savedDates`에 `"{exchangeId}_{컬럼명}" → "2026.08.27"` **문자열 맵**으로만 존재 | `substitution_plan_provider.dart:9, 149` |
| 개인 시간표 | **날짜 있음.** 주차 칩 + 컬럼명 `월_5_2026.06.10` + base·overlay 합성 | `exchange_week_collector.dart`, `personal_timetable_datasource.dart:73` |

⇒ **날짜는 이미 시스템 안에 있다.** 다만 *시간표 모델*이 아니라 *인쇄 데이터*에 붙어 있고,
   개인 시간표만 그것을 읽어 주차별로 그린다. **진실원본이 둘로 갈라져 있다.**

#### 10.2.1 정정 — 교체 적용은 "영구 변형"이 아니라 "토글되는 오버레이"였다 (2026-08-30, 4단계 착수 시 발견)

§10.2 최초 작성 시 `exchange_service.dart`의 `moveTime` 호출만 보고 "교체 실행이
마스터 시간표를 영구히 변형한다"고 적었으나, 4단계에서 호출부를 추적한 결과
**실제 구조는 이미 토글 가능한 오버레이였다.**

```
평소                  마스터 timeSlots = 엑셀 원본 그대로
  ↓ 교체 뷰 ON  (enableExchangeView, exchange_view_provider.dart:91)
     1) 활성 교체 목록 전체를 순회하며 원본 셀을 backupData에 백업
     2) 같은 목록을 timeSlots에 moveTime으로 파괴적 적용
  ↓ 교체 뷰 OFF (disableExchangeView, :201)
     backupData를 역순으로 복원 → 원본 상태로 되돌아감
```

**그래서 P1~P3의 진짜 원인은 "파괴적 변형" 자체가 아니라, 그 오버레이가
"전체 활성 교체"를 대상으로 하고 주(週) 개념이 없다는 점이다.** 교체 뷰를 켜면
8/27 교체와 9/3 교체가 **동시에** 같은 날짜 없는 그리드에 겹쳐 적용된다.

이 정정은 B안의 방향을 바꾸지 않는다 — 오히려 **전환을 더 쉽게 만든다**:

| | 기존 | B안 전환 후 |
|---|---|---|
| 표시 상태 생성 | 백업 → 파괴적 적용 → 복원 (3단계, 상태 있음) | `ResolvedWeek.of(base, events, week)` (1단계, 순수 함수) |
| 대상 범위 | 전체 활성 교체 | 그 주의 이벤트만 |
| 백업/복원 코드 | 필요 (`backupData`, `backedUpCount` 증분 관리) | **전부 불필요 — 원본을 건드리지 않으므로** |

⇒ 4단계의 실질적 핵심은 "`moveTime` 제거"보다 **"백업/복원 메커니즘을 `ResolvedWeek`
합성으로 대체"**다. `exchange_view_provider.dart`의 백업 관련 코드 약 260줄
(`_backupOriginalSlotInfo`~`_findTimeSlotByBackupInfo`)이 삭제 대상이 된다.

**추가 발견 — 실행 로직 중복**: `exchange_view_provider.dart`와
`personal_exchange_view_manager.dart`에 `_executeOneToOne/Circular/Dual/Supplement`
4개 메서드가 거의 동일하게 중복되어 있다. `ResolvedWeek`로 전환하면 양쪽 모두
같은 합성 함수를 쓰게 되어 이 중복도 함께 사라진다.

### 10.3 이 구조에서 실제로 터지는 것

| # | 문제 | 설명 |
|---|---|---|
| **P1** | **주(週) 오염** | 8/27 교체가 9/3·9/10 목3에도 계속 반영된 것처럼 보인다. 다음 주에 교체하려면 이전 주 것을 되돌려야 하고, 되돌리면 8/27 계획서의 근거가 사라진다 |
| **P2** | **같은 칸 재사용 불가** | 같은 요일·교시에 다른 날짜의 교체 2건을 못 넣는다 — 원본 셀이 이미 `clear()`됐기 때문. **실사용에서 자주 발생**(격주 출장, 매주 목요일 연수, 1·2주차 / 3·5주차 혼재) |
| **P3** | **교사 간 상호 오염** | §1-6 "교체 상태 시간표 전체 공유" + 날짜 없음의 결합. A교사의 8/27 교체 후 상태를 기준으로 B교사의 **9/3** 건이 검증된다. 9/3의 목3은 원본이어야 하는데 **다른 날짜의 교체가 서로를 잘못 제약**한다 |
| **P4** | **undo ≠ 날짜 순서** | undo는 실행 시각 LIFO(최근 10개, `exchange_history_service.dart:116,187`). 8/28 건을 취소하려면 그 뒤에 만든 8/20 건까지 딸려 되돌아간다 |
| **P5** | **날짜가 사후 입력** | 교체를 먼저 실행하고 결보강 탭에서 날짜를 나중에 넣는다 → 교체 시점에 "그 날짜에 이 칸이 정말 비어 있나"를 검증할 수 없다. 결강일과 교체일이 다른 주여도 통과한다 |
| **P6** | **연도 추정 폭탄** | `toYearMonthDayFromMonthDay`가 없는 연도를 `DateTime.now().year`로 채운다(`date_format_utils.dart:80,97`). 1학기 시간표를 12월에 열면 결강일 "3.5"가 엉뚱한 해로 붙는다. **다중 시간표(학기별)에서 특히 위험** |
| **P7** | **교체불가도 날짜 없음** | "9/1 3교시는 지필평가라 교체 불가"를 표현할 수 없다. 요일 단위로만 막혀 영구 제약이 된다 |

### 10.4 채택안 — B안: Base + 이벤트 오버레이

> **원본 시간표는 절대 고치지 않는다. 교체는 "날짜가 붙은 메모지"로만 쌓고,
> 화면은 볼 때마다 [원본 + 그 주 메모지]를 겹쳐서 계산한다.**

**현재 — 종이 한 장을 지우개로 고쳐 씀**

```
        엑셀 원본 시간표 (요일×교시, 날짜 없음)
        ┌──────┬──────┬──────┐
   3교시 │ 월   │ 수   │ 목   │
        │ 수학  │ 체육  │ 국어  │
        └──────┴──────┴──────┘
                          │
        8/27 교체 실행 ────┤  ← TimeSlot.moveTime()
                          ↓     이 종이를 직접 지우고 고쳐 씀
        ┌──────┬──────┬──────┐
   3교시 │ 수학  │ 체육  │ (빔) │   ← 목3이 지워짐
        └──────┴──────┴──────┘

        ⚠ 이 종이는 딱 한 장뿐이다.
          8/27뿐 아니라 9/3, 9/10, 9/17 … 전부 "목3은 비었음"이 된다.
```

**B안 — 원본은 그대로, 메모지를 날짜별로 얹음**

```
[1] 원본 (읽기 전용 · 절대 안 고침)      [2] 교체 이벤트 = 날짜 붙은 메모지
    ┌──────┬──────┬──────┐              ┌──────────────────────────────┐
3교시│ 월   │ 수   │ 목   │              │ ① 8/27(목)3 국어 → 8/28(금)2 │
    │ 수학  │ 체육  │ 국어  │              │ ② 9/03(목)3 국어 → 9/04(금)5 │
    └──────┴──────┴──────┘              │ ③ 9/17(목)3 국어 → 9/18(금)1 │
              │                          └──────────────────────────────┘
              │                                        │
              └──────────────┬─────────────────────────┘
                             ↓
                   합성 (볼 때마다 계산 · 저장 안 함)

```

| 원칙 | |
|---|---|
| 1 | 원본은 **절대** 안 바뀐다 (엑셀 파싱 결과 그대로 유지) |
| 2 | 교체는 **"언제"를 가진 이벤트 1건**으로만 저장된다 |
| 3 | 화면·검증·PDF는 모두 **`ResolvedWeek(주)` 합성 결과** 위에서 동작한다 |

### 10.5 다중 교사 / 부장교사 전교 관리

**현재 구조에서 벌어지는 일**

```
종이 한 장을 모든 교사가 공유 (§1-6)

  1) 홍길동 8/27 건 실행     → 목3 지워짐
  2) 김철수 9/03 건 만들려고 목3 클릭
       화면이 보여주는 것: "목3 = 비었음"
       판정:               "교체할 수업이 없습니다" ✗

  ✗ 8/27과 9/03은 완전히 다른 날인데, 홍길동의 교체가 김철수의 교체를 막는다.
```

**B안에서**

```
  1) 홍길동 8/27 건 → 이벤트 ①(8/27)
  2) 김철수 9/03 건 → 검증 기준 = 원본 + [9월1주 이벤트]
                       이벤트 ①은 8월4주 → 보이지 않음
                       목3 = 국어(원본) → 교체 가능 ✓
```

**단, "같은 주 안의 충돌"은 여전히 잡는다 — 이건 진짜 충돌이다**

```
        9월1주 (9/1 ~ 9/5)
        ┌───────────────────────────────────────────┐
        │ 홍길동 건: 9/03(목)3 → 9/04(금)5 에 넣음    │
        │ 김철수 건: 9/04(금)5 를 또 쓰려고 함  ⚠     │
        └───────────────────────────────────────────┘
                     ↓
        같은 주 + 같은 칸 = 진짜 충돌 → 경고
```

⇒ **B안은 §1-6의 "교체 상태 공유"를 폐기하지 않는다. 공유의 범위를 "영원히"에서
   "그 주 안에서"로 좁힐 뿐이다.** 이것이 P3의 해법이며, 부장교사가 여러 교사의
   교체를 한 화면에서 관리할 수 있게 하는 전제 조건이다.

**부장교사 전교 관리 화면 (교체 관리 화면 개편안)**

```
┌─────────────────────────────────────────────────────────────┐
│  교체 관리                                                   │
│  ┌──────┬──────┬──────┬──────┬──────┐                      │
│  │8월4주│9월1주│9월2주│9월3주│＋    │  ← 주차 바              │
│  │  ●2  │  ●3  │      │  ●1  │      │  ● = 그 주 교체 건수     │
│  └──────┴──────┴──────┴──────┴──────┘                      │
│   선택: 9월1주 (9/1 ~ 9/5) · 교체 3건 · 교사 2명              │
├─────────────────────────────────────────────────────────────┤
│        월(9/1)   화(9/2)   수(9/3)   목(9/4)   금(9/5)       │
│  홍길동  …        …        [빔]▲     [국어]▼   …            │
│  김철수  …        …        …         …        [빔]▲         │
│                                    ▲결강  ▼보강              │
├─────────────────────────────────────────────────────────────┤
│  이 주의 교체 (3건)                                          │
│   · 홍길동  9/03(수)3 국어 → 9/04(목)2        [계획서1 ▼]    │
│   · 홍길동  9/03(수)5 국어 → 9/05(금)1        [계획서1 ▼]    │
│   · 김철수  9/05(금)4 음악 → 9/02(화)6        [미지정  ▼]    │
└─────────────────────────────────────────────────────────────┘
```

| 대책 | 내용 |
|---|---|
| **주차 바** | 교체 화면에 도입. 어느 주를 보고 있는지가 항상 화면에 있어야 한다 |
| **교체 목록 주차 그룹핑** | 현재 평면 리스트 → 주차별로 접어서 표시 |
| **소유 교사 열** | 누가 만든 건인지 표시 (전교 관리 시 필수) |
| **충돌 검사 범위 축소** | 같은 주 안에서만. 다른 주는 검사 자체를 하지 않는다 |
| **주차별 일괄 출력** | "9월1주 전체 3건 출력" — 부장교사가 주 단위로 처리 |

#### 교체 화면 Before / After

현재 그리드는 **행 = 교사, 열 = `{요일}_{교시}`**(`syncfusion_timetable_helper.dart:61`),
요일이 스택 헤더로 묶인 구조다. **이 구조 자체는 바뀌지 않는다.**

```
【현재】
┌──────┬───────────┬───────────┬───────────┐
│ 교사 │    월     │    화     │    목     │
│      │  3   4   5│  3   4   5│  3   4   5│
├──────┼───────────┼───────────┼───────────┤
│홍길동│ 수학  ·  ·│  ·   ·   ·│ 국어  ·  ·│
│김철수│  ·   ·   ·│ 음악  ·  ·│  ·   ·   ·│
└──────┴───────────┴───────────┴───────────┘
              ▲ 날짜가 없다 — 이 표는 "어느 주"인지 모른다

【변경 후】
┌───────────────────────────────────────────┐
│ ◀ 8월4주 ┃9월1주┃ 9월2주  9월3주 ▶  ★신규 │
│     ●2   ┃ ●3  ┃          ●1              │
│ 9월1주 (9/1 ~ 9/5) · 교체 3건 · 교사 2명   │
├──────┬───────────┬───────────┬────────────┤
│ 교사 │ 월 (9/1)  │ 화 (9/2)  │ 목 (9/4)   │ ★날짜
│      │  3   4   5│  3   4   5│  3   4   5 │
├──────┼───────────┼───────────┼────────────┤
│홍길동│ 수학  ·  ·│  ·   ·   ·│〔빔〕 ·  · │
│김철수│  ·   ·   ·│ 음악  ·  ·│  ·   ·   · │
└──────┴───────────┴───────────┴────────────┘
```

신규 요소는 **주차 바 1줄**과 **요일 헤더의 날짜 괄호** 둘뿐이다. 모드 버튼, 셀 클릭,
색상 표시(초록/노랑/빨강), 내 시간표 행 하이라이트, 교체불가 우클릭은 모두 그대로다.

**색상 판정이 그 주 기준으로 계산되는 것이 이 변경의 핵심이다.** 같은 목3 셀이라도
8월4주에서는 "이미 교체됨", 9월2주에서는 "교체 가능"으로 다르게 나와야 한다.

**교체 실행 시 날짜 입력은 늘지 않는다.** `주차 + 요일 = 날짜`가 자동 확정되므로,
오히려 결보강 탭에서 날짜를 타이핑하던 작업이 사라진다.

#### 주차 바 동작 규칙 (확정)

| 항목 | 결정 | 근거 |
|---|---|---|
| **칩 건수 세기** | **결강일이 속한 주에만 1건**으로 센다 | 교체의 주인은 결강이다. 칩 숫자의 합이 실제 교체 건수와 일치해야 목록·출력 건수와 어긋나지 않는다 |
| **주 경계를 넘는 교체 표시** | 결강일·교체일 중 **하나라도** 그 주에 걸리면 **화면에는 반영**한다 | 결강 금(9/5) → 보강 월(9/8)이면 9월1주엔 결강 칸이, 9월2주엔 보강 칸이 보인다. 세는 것과 보이는 것은 규칙이 다르다 |
| **칩에 없는 주** | 교체가 0건인 주도 `◀ ▶`로 이동해 열람할 수 있다 | 칩은 "교체가 있는 주"만 띄우지만, 새 교체를 만들려면 빈 주로도 갈 수 있어야 한다 |
| **기본 선택 주** | 교체가 있는 첫 주. 없으면 이번 주 | `ExchangeWeekCollector.defaultWeekMonday`의 기존 규칙을 그대로 따른다 |

```
주 경계를 넘는 교체 1건 — 결강 금(9/5) → 보강 월(9/8)

  ◀  9월1주   9월2주  ▶       칩 숫자: 결강일 기준이므로 9월1주에만 ●1
      ●1      (없음)

  [9월1주] 금(9/5) = 〔빔〕▲   ← 화면에는 양쪽 다 나타난다
  [9월2주] 월(9/8) = 국어  ▼
```

#### 되돌리기 동작 (확정)

**전체 최근 1건을 되돌리되, 그 교체가 속한 주로 화면을 자동 이동한다.**

```
실행 순서:  ① 8/27(8월4주)  ② 9/03(9월1주)  ③ 8/28(8월4주)

[9월1주]를 보는 중에 [되돌리기]
  → ③ 8/28 건을 되돌림 (전체 최근)
  → 화면을 8월4주로 자동 전환
  → 스낵바: "8월4주의 교체를 되돌렸습니다"
```

- **화면이 점프하므로 안내는 필수다.** 없으면 "버튼을 눌렀더니 화면이 멋대로 바뀌었다"가 된다
- `ExchangeHistoryService`는 **수정하지 않는다.** `undoLastExchange()` 반환값의
  `weekMonday`로 주차 선택 상태를 갱신하는 후처리만 추가한다
- "보고 있는 주의 마지막 교체만 되돌리기"는 채택하지 않는다 — `maxUndoItems = 10`
  (`exchange_history_service.dart:37`) 때문에 **주마다 되돌리기 가능 여부가 달라지고,
  그 이유가 화면에 드러나지 않는다.** 특정 건을 지우는 용도는 교체 목록의 개별 삭제
  (`removeFromExchangeList`, `:128`)가 이미 담당한다 — 되돌리기는 "방금 한 것 취소",
  목록 삭제는 "특정 건 제거"로 역할을 나눈다

### 10.6 데이터 구조 변경

```dart
// lib/models/exchange_history_item.dart
class ExchangeHistoryItem {
  final DateTime absenceDate;       // 결강일 — 신규 · 필수
  final DateTime substitutionDate;  // 교체일 — 신규 · 필수
  DateTime get weekMonday => WeekDateCalculator.getWeekMonday(absenceDate);
  // timestamp는 '실행 시각'으로 의미 유지 (감사 로그 용도)
}

// lib/models/timetable_registry.dart
class TimetableRegistryEntry {
  final DateTime? semesterStart;    // 신규 — 학기 시작일
  final DateTime? semesterEnd;      // 신규 — 학기 종료일
}
```

| 항목 | 결정 |
|---|---|
| 날짜 저장 타입 | **`DateTime` 고정.** `"월.일"` 문자열 저장 금지 → P6 원천 차단 |
| 학기 기간 | 시간표 등록 다이얼로그에서 입력받는다. 주차 칩 범위 확정 + 학기 밖 날짜 입력 차단 |
| `savedDates` 문자열 맵 | **제거.** 진실원본은 `ExchangeHistoryItem`으로 단일화. 두 진실원본 공존은 §9-1·§9-5와 같은 종류의 사고를 반복시킨다 |
| 교체불가 셀 | `date?` 필드 추가. `null` = 매주 반복(현행), 값 있음 = 그 날짜만 → P7 |
| 저장 파일 | `exchange_list_{timetableId}.json` 유지 (주차별 파일 분리 안 함 — 주 경계를 넘는 교체를 표현할 수 없게 된다) |

#### 구 데이터 처리 — 마이그레이션 없음 (§4·§6-2 정책 계승)

기존 데이터의 자동 이전은 **제공하지 않는다.** 다만 "이전하지 않음"과 "아무 처리도 하지
않음"은 다르다. 구 형식 파일에는 `absenceDate`가 없어 그대로 두면 다음이 발생한다.

- `ExchangeHistoryItem.fromJson`이 예외 → **앱 시작 실패**
- 또는 null 날짜가 `ResolvedWeek`까지 흘러들어 **조용한 오작동**

⇒ **스키마 버전으로 명시적으로 차단한다.**

```
exchange_list_{timetableId}.json
  { "schemaVersion": 2,          ← 신규. 없거나 2 미만이면 구 형식
    "items": [ … ] }
```

| 상황 | 동작 |
|---|---|
| `schemaVersion` 누락 또는 < 2 | **로드하지 않는다.** 파일을 `*.v1.bak`으로 이름만 바꿔 보관하고 빈 목록으로 시작 |
| 사용자 안내 | 시작 시 1회 안내 — "이전 버전의 교체 목록은 날짜 정보가 없어 사용할 수 없습니다. 교체를 다시 등록해 주세요. (이전 데이터는 `*.v1.bak`으로 보관됩니다)" |
| `substitution_plan_data_{id}.json`(`savedDates`) | 동일하게 미참조 + 백업 |
| 계획서(`print_profiles_{id}.json`) | **유지.** 날짜와 무관하므로 스키마가 바뀌지 않는다 |
| 시간표 본문(`timetable_data_{hash}.json`) | **유지.** 원본 엑셀 파싱 결과이며 이번 변경의 영향을 받지 않는다 |

- **조용히 지우지 않는다.** 백업 + 안내가 없으면 사용자에게는 "교체 목록이 사라진 버그"로 보인다
- **조용히 임의 날짜를 부여하지 않는다.** 없는 날짜를 추정해 채우면 잘못된 주에 교체가 붙는다
- 백업 파일은 앱이 다시 읽지 않는다 (§7-8 "레거시 폴백 제거" 원칙 유지)

### 10.9 리스크

1. **구 데이터의 조용한 유실**: 마이그레이션을 하지 않으므로 사용자는 교체 목록을 잃는다.
   **백업(`*.v1.bak`) + 시작 시 안내가 없으면 "버그로 데이터가 날아갔다"로 인식된다.**
   구현 순서상 `schemaVersion` 가드를 날짜 필드 추가와 **같은 커밋**에 넣어야 한다 —
   나중에 붙이면 그사이 버전에서 앱이 시작조차 못 한다
2. **날짜 없는 교체 건은 존재할 수 없게 한다**: `absenceDate`를 nullable로 두면 P5가
   그대로 남는다. 구 데이터를 안 읽기로 한 이상 **필수(non-null) 필드로 선언**해
   "날짜 미지정 교체"라는 상태 자체를 만들지 않는다
3. **성능**: `ResolvedWeek` 합성이 렌더링마다 돌면 §CLAUDE.md의 "1초 미만" 요구와 충돌할 수
   있다. 주(週) 단위 메모이제이션 필수 (`cell_cache_manager.dart`의 enum 캐시 패턴 재사용)
4. **§1-6과의 관계**: "교체 상태 시간표 전체 공유"는 **폐기가 아니라 범위 축소**다.
   문서·코드 주석에서 이 점을 명확히 하지 않으면 다음 작업자가 공유를 되돌릴 위험이 있다
5. **`exchangeId` vs `item.id`**: §6-1의 두 식별자 공존 문제가 날짜 도입으로 더 복잡해진다.
