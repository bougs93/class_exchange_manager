# 계획서 중심 운영 계획서

> 상태: 부분 구현 중 (2026-10-02)
> - 7장 Q4 칩 배치 확정 → `PlanSelectorChip` 신규 + 교체 화면 주 바 2행에 배치 완료
> - 날짜 범위·건수 텍스트 삭제, 스위치→버튼, 주 이동 버튼 강조, 범위 밖 주황 테두리 주 칩으로 이관 완료
> - 남은 7장 Q1~Q3 미확정 (교체 확인 문구, 출력 선택 통합, 안내 필터)
> 작성 기준: 코드 현황 조사 (`printProfile`·`profileId`·`lastUsedProfile` 참조 분포)

## 1. 배경

계획서 이름(예: `결보강 26.09.30`)은 사실상 앱 전체의 기준 키다.

- 교체 건(`ExchangeHistoryItem`)은 `profileId`로 계획서에 귀속된다
- 결보강 출력의 체크 상태·PDF 설정은 계획서 단위로 저장된다
- 계획서 삭제는 연결된 교체 건까지 함께 지운다 (2026-09-30 확정)

그런데 계획서를 고르고 확인하는 UI는 **계획서 탭(내용 수정·결보강 출력)에만** 있다.
"준비를 제외한 모든 항목의 기준"이 정작 그 화면들에서는 보이지 않는다.

## 2. 현황 조사 (2026-10-01 기준)

| 화면 | 계획서 인식 | 비고 |
|---|---|---|
| 준비 (홈) | × | 시간표·교사 선택만. 계획서 개념 없음 (요구사항상 제외 유지) |
| 교체 | × | `timetable_grid_section` 내 profile 언급 1건(주석 수준). 실행된 교체가 어느 계획서에 들어가는지 화면에서 모름 |
| 계획서 > 내용 수정 | ○ | 이름 선택·생성·수정·삭제, 행별 지정. 유일한 관리 지점 |
| 계획서 > 결보강 출력 | ○ | 출력 대상 계획서 선택. 단, 내용 수정과 선택 상태가 따로 노님 (`_selectedProfileId` vs `_selectedPlanId`) |
| 안내 (교사·학급) | × | 교사·학급 기준 메시지. 어느 계획서 소속 교체인지 표시 없음 |
| 개인 시간표 | × | 계획서 개념 없음 |
| 설정·기타 | × | 계획서 개념 없음 |

데이터층은 준비됐다 (`profileId`, `lastUsedProfileId`, 행별 `deselectedGroupIds`).
부족한 것은 **보여주기 + 고르기**다.

## 3. 목표

1. 준비를 제외한 모든 화면에서 "지금 보고 있는 계획서"를 알 수 있다
2. 계획서 전환이 어느 화면에서든 1~2탭 안에 된다
3. 교체 실행은 현재 계획서에 자동 귀속된다 (나중에 옮기는 구조 유지)

### 비목표

- 준비 화면에 계획서 개념 추가 (제외 유지)
- 계획서별 권한·공유 (1인 운영 전제)
- 과거 미지정 데이터의 소급 귀속 (미지정은 미지정으로 둔다)

## 4. 설계안

### 4.1 단일 진실 원본: `lastUsedProfileId`

이미 `PrintProfileStore.lastUsedProfileId`가 있다. 이를 **전역 현재 계획서**로
격상하고, 화면별 로컬 선택 상태(`_selectedPlanId`, `_selectedProfileId`)는
이 값의 캐시로 취급한다 (불일치 시 스토어 값 우선).

### 4.2 공통 UI: 현재 계획서 칩

모든 대상 화면 상단에 동일한 칩을 둔다.

```
[계획서: 결보강 26.09.30 ▾]
```

- 탭하면 계획서 목록 (교사별 그룹, 현재 체크) → 선택 시 전역 전환
- 새 계획서 만들기는 내용 수정으로 연결 (생성 UI는 한 곳에만 둔다)
- 교체 화면에서는 칩이 "이번 교체가 들어갈 계획서"임을 툴팁으로 명시

### 4.3 화면별 반영

| 화면 | 변경 |
|---|---|
| 교체 | 상단에 칩 추가. 교체 실행 시 현재 계획서로 자동 귀속 (`assignProfile`). 단, 교체 전 확인 문구에 계획서명 포함 ("`결보강 26.09.30`에 기록됩니다") |
| 결보강 출력 | 로컬 선택을 없애고 전역값 그대로 사용 (두 화면 선택 따로 노는 문제 해소) |
| 안내 | 메시지 그룹 헤더에 계획서명 병기 (예: `정원길 · 결보강 26.09.30`). 계획서별 필터는 2차로 검토 |
| 개인 시간표 | 칩만 표시 (읽기 화면이므로 귀속 변경 없음) |
| 내용 수정 | 그대로 (관리 지점 유지). 단, 전역 전환과 양방향 동기화 |

### 4.4 교체 실행 시 자동 귀속 규칙

- 실행 순간 전역 현재 계획서가 있으면 그 `profileId` 부여
- 전역 미지정이면 미지정 그대로 (나중에 행별 지정 가능 — 기존 흐름 유지)
- 되돌리기·삭제는 귀속과 무관하게 기존 규칙 유지

## 5. 단계별 작업

1. **기반**: `lastUsedProfileId` 읽기 헬퍼 + 공통 계획서 칩 위젯 신규 (신규 파일 1개)
2. **교체 화면**: 칩 배치 + 실행 시 자동 귀속 + 확인 문구. 기존 테스트 + 신규 테스트
3. **결보강 출력**: 로컬 선택 제거 → 전역값 사용. 따로 놀던 선택 동기화 이슈 해소 확인
4. **안내 화면**: 그룹 헤더에 계획서명 병기
5. **개인 시간표**: 칩 표시만
6. **회귀**: `flutter analyze` + 전체 테스트 + 교체→안내→출력 흐름 수동 확인

## 6. 리스크

- **미지정 데이터**: 기존 미지정 교체는 칩에 안 잡힌다. 필터·합산에서 제외되는 것이 맞는지 확인 필요
- **두 화면 선택 통합(3번)**: 현재 따로 노는 것이 우연인지 의도인지 코드 이력 확인 필요. 통합 시 기존 사용자 동선 변경됨
- **안내 메시지 길이**: 헤더에 계획서명이 붙으면 모바일·좁은 화면에서 잘림 가능 → ellipsis 처리

## 7. 결정 필요 사항 (사용자 답변 후 착수)

1. 교체 실행 확인 문구에 계획서명을 넣는 것에 동의하는가?
2. 결보강 출력의 로컬 선택을 전역값으로 통합해도 되는가? (현재 따로 노는 동작을 쓰고 계셨다면 유지)
3. 안내 화면에 계획서별 필터까지 필요한가, 헤더 병기로 충분한가?
4. 칩의 위치·문구 (`[계획서: … ▾]`案) 괜찮은가?
